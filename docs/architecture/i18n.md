# Internationalization

Locales: **en** (reference), **pt-BR**, **pt-PT**, **es**, **fr**, **it**,
**de**. Everything a person reads is translated: both app windows, the
extension popup and store listing, and the SDK's optional error texts.
Developer-facing text (CLI output, error `message`, logs, docs) is English.

## Files

`i18n/<locale>.toml` at the repository root, one per locale. `en.toml`
defines the keys; every other file must have exactly the same keys and
placeholders.

```toml
[confirm]
# Window title in the task bar. {site} is the host or the program name.
window_title = "Sign for {site} — SignLocal"

[cert.expires_in]
one = "Expires in {count} day"
other = "Expires in {count} days"
```

- Keys are dotted paths (`confirm.window_title`); sections group an area.
- `{name}` placeholders, `name` in `[a-z_]+`; no escaping, no nesting.
- A table whose keys are only CLDR categories (`zero one two few many other`)
  is a plural; `other` is required; `{count}` is filled automatically.
- Comments above a key are translator notes and stay in every locale.
- Why TOML: comments for translators, readable diffs, trivially parsed.

## Rust (`websign-i18n`)

- `build.rs` reads `en.toml` and generates one constant per key in
  `websign_i18n::k` (`k::CONFIRM_WINDOW_TITLE: Key`,
  `k::CERT_EXPIRES_IN: PluralKey`). A misspelled key does not compile.
- All seven files are embedded (`include_str!`); no runtime file access.
- `Catalog::new(Locale::from_system())`, `catalog.tr(k::X).arg("site", s)`,
  `catalog.plural(k::Y, n)`; `Display` renders.
- Fallback chain: `pt-BR → pt-PT → en`, `pt-PT → pt-BR → en`, others `→ en`.
  A missing key in a shipped build is impossible (CI), but the chain keeps the
  app readable if it happened.
- Locale choice: OS locale (`sys-locale`), matched to the closest shipped
  locale (`pt` → pt-BR, `es-MX` → es, `de-AT` → de).
- Plural rules: CLDR cardinal rules for integers as one pure function
  (`websign_i18n::plural::category`). Dates: `dd/mm/yyyy` (pt, es, fr, it),
  `dd.mm.yyyy` (de), `14 Mar 2027` (en); times 24-hour. No ICU.

## Extension

`cargo xtask gen` converts the `[popup]`, `[store]` and `[extension]` sections
into `extension/public/_locales/<xx_YY>/messages.json` (`popup.ready_title` →
`popup_ready_title`, `{version}` → `$version$` with a `placeholders` entry).
The popup uses `browser.i18n.getMessage`, which follows the browser's
language; the stores show the translated name and description. The popup has
no plurals (`chrome.i18n` has none); the checker enforces it.

## SDK

`cargo xtask gen` turns `[site.errors]` into `sdk/src/messages.gen.ts`,
exported only from `@websign/sdk/messages`, so the main entry stays tiny and
dependency-free.

## CI

`cargo xtask check i18n` (`websign_i18n::check::check_locale`) fails on any
missing or extra key, placeholder mismatch, plural without `other`, plural in
extension sections, or a store description over 132 characters — for **all**
seven locales. Translations are completed by the i18n track; until then the
non-English files are copies of `en.toml`.

## Adding a string

1. Add the key with a translator comment to `en.toml`.
2. Add it to the six other files (English text until translated).
3. Use `k::THE_KEY` in Rust, or run `cargo xtask gen` for the extension/SDK.
