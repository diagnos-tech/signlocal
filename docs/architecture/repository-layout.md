# Repository layout

```

package.json  bun.lock  biome.json  tsconfig.base.json

devices.json  devices.schema.json  LICENSE-CC0
i18n/                   en (reference), pt-BR, pt-PT, es, fr, it, de
crates/

  websign-protocol/     wire types, framing, errors, verification code (Apache-2.0)

  websign-i18n/         keys, locales, plurals, dates

  websign-devices/      USB, PC/SC, live events, devices.json hints
```

Deviations from the first sketch in the old plan, and why:

- **`crates/websign-project`**: every crate that names the product, the
  native host or extension IDs reads them from one place generated from
  `project.toml`; Apache-2.0 so the Rust client can use it.
- **`crates/websign-ui-model`**: the confirmation state machine, list rules
  and diagnostics report are pure; outside the app crate they are
  blind-TDD'able without compiling egui/wgpu, and the host can share the list
  rules (initial selection) with the window.
- **`crates/websign-i18n` as a crate** (not inside `app/`): the key generator,
  plural rules and the locale checker are used by the app and by `xtask`.
- **`i18n/` at the root** (not `app/i18n`): the extension and the SDK are
  generated from the same files.
- **Protocol and client crates are Apache-2.0**, so the GPL never reaches a
  program that only talks to the app. The verification-code algorithm lives
  in the protocol crate for the same reason.

## Conventions

- Rust: one concept per file, files under ~200 lines, tests next to the code
  (`mod tests;` in `<module>/tests.rs`) or in `tests/` for public-API tests.
  `unsafe` only in platform adapters, each block with `// SAFETY:`.
- TypeScript: one module per concern under `src/<area>/`; generated code only
  under `src/generated/`.
- Names explain; comments explain **why**. Pending maintainer decisions are
  `TODO(gustavo)`; nothing refers to plans or phases in code.
- Every component root has a `README.md` (what it is, how to build/test it,
  where its contract is); every pure component has a `SPEC.md`.

## SUMMARY.md

Every folder has a `SUMMARY.md`: a map of the folder, one line per entry,
enforced by `cargo xtask check summaries`.

### Format

```markdown
# <folder path from the repository root, e.g. crates/websign-core/src/cert>

<Optional paragraph, at most 3 lines: what this folder is and why it exists.>

- `file.rs` — what it is and why it is here
- `sub/` — what the subfolder holds
- `*.der` — test certificates generated by `gen/` (glob rows cover many files)
```

Rules the checker enforces:

1. The file is named exactly `SUMMARY.md` and starts with a `# ` heading.
2. Entries are Markdown list items of the form ``- `NAME` — DESCRIPTION``
   (em dash `—`, or ` - ` accepted); the description is non-empty.
3. `NAME` is a file name, a folder name with a trailing `/`, or a glob
   (`*`, `?`) matching several files of this folder.
4. Every file and folder in the folder — except `SUMMARY.md` itself and
   ignored paths — is covered by **exactly one** entry (a literal name wins
   over a glob).
5. Every entry matches at least one existing file or folder (no stale rows).
6. Ignored everywhere: `.git/`, `node_modules/`, `target/`, `dist/`,
   `.output/`, `.wxt/`, and anything `.gitignore` ignores. The frozen Phase-0
   kit (`docs/prototypes/kit/**`) follows the same format but is not checked.
7. Folders named `generated/` get their `SUMMARY.md` from the generator.

Order: folders first, then files, alphabetically — recommended, not enforced.
